# 快速 Winograd 内积算法与性能对比

用 C++17 实现 Winograd 内积恒等式，并对比它与朴素算法的**运算量**和**实际耗时**。
包含单个内积、批量内积（矩阵乘法）、神经网络线性层 `Y = X W^T + b`，以及
奇偶长度、非方阵的正确性检查。

```
Winograd/
├── include/winograd.hpp   # 内积 / 矩阵乘法接口
├── include/linear.hpp     # 线性层接口
├── src/winograd.cpp       # 朴素 / Winograd 实现与运算量统计
├── src/linear.cpp         # 线性层实现
├── src/bench.cpp          # 正确性检查 + 性能测试
├── docs/linear_layer.md   # 线性层算法的完整推导与实测
├── Makefile
└── README.md
```

线性层的算法推导、缓存策略、运算量和实测结果见
[docs/linear_layer.md](docs/linear_layer.md)。

## 1. 算法原理

对一对元素有恒等式

```
a0*b0 + a1*b1 = (a0 + b1) * (a1 + b0) - a0*a1 - b1*b0
```

把长度 `n = 2m` 的内积两两分组：

```
a·b = Σ_{k=0}^{m-1} (a_{2k} + b_{2k+1}) * (a_{2k+1} + b_{2k})
      - X(a) - Y(b)
```

其中

```
X(a) = Σ_k a_{2k}   * a_{2k+1}
Y(b) = Σ_k b_{2k}   * b_{2k+1}
```

`n` 为奇数时最后一项 `a[n-1]*b[n-1]` 直接计算。代码里对应：

- `dot_winograd`：完整公式，每次调用重新计算 `X(a)`、`Y(b)`；
- `dot_winograd_precomputed`：`X(a)`、`Y(b)` 由调用方缓存时使用；
- `matmul_winograd`：对 `C = A*B`，按行缓存 `X_i`、按列缓存 `Y_j`，
  每个元素只需 `n/2` 次乘法。

## 2. 运算量

长度 `n` 的内积（`n` 为偶数）：

| 算法 | 乘法 | 加法 |
| --- | ---: | ---: |
| 朴素 | `n` | `n-1` |
| Winograd（重算 X、Y） | `3n/2` | `5n/2 - 1` |

**单个内积并不会更快**：乘法反而增加到 1.5 倍。原因是 `X(a)`、`Y(b)` 的
自乘积必须重新计算。只有这些量被大量内积共享时，Winograd 形式才划算。

`n×n` 矩阵乘法：

| 算法 | 乘法 | 加法 |
| --- | ---: | ---: |
| 朴素 | `n³` | `n³ - n²` |
| Winograd | `n³/2 + n²` | `1.5n³ + n²` |

乘法减半，加法增加，**总浮点运算量基本不变**（都约为 `2n³`）。这正是实测
中墙钟时间只有小幅改善甚至持平的原因：现代 CPU 的乘法与加法吞吐相同，
Winograd 的收益来自更短的依赖链和更好的指令级并行，而不是乘法数量减少。
历史上乘法远比加法昂贵，这类算法才有明显优势。

## 3. 构建与运行

```bash
cd Winograd
make                  # 默认 -O2
./bench               # 完整测试（内积、矩阵乘法、线性层）
./bench --quick       # 较小规模，快速运行
./bench --dot-sizes 1024,65536 --mm-sizes 128,256
./bench --fc-shapes 256:1024:1024,128:784:256   # 自定义线性层形状
make OPT="-O3 -march=native"   # 针对本机优化
```

`make run` 等价于 `make && ./bench`。

矩阵乘法的默认尺寸避开了 2 的幂（48、96、120、160、200、240、320），
因为行跨度为 1/2/4 KB 时会出现严重的 cache 冲突。可以用
`--mm-sizes 128,256` 观察这一现象。

结论：

- 单个内积：Winograd 乘法是朴素算法的 1.5 倍，墙钟时间基本持平
  （依赖链更短，部分抵消了多余运算）；
- 矩阵乘法：乘法数量减半，48–200 阶约快 1.2–1.4 倍，240 阶以上基本持平；
- 正确性：最大相对误差约 `1e-14`（double 舍入量级）。

## 5. 数值稳定性

Winograd 公式存在相消：`(a0+b1)(a1+b0) - a0a1 - b1b0` 中各项量级可能远大于
最终结果。对条件数很大的数据，误差会比朴素求和略大。测试中随机 `[-1,1]`
数据的相对误差仍在 `1e-14` 量级；对精度敏感的场景应使用补偿求和或避免该
变换。

## 6. 神经网络线性层

同一恒等式可直接用于 `Y = X W^T + b`：按行缓存 `X` 的自乘积，按输出行缓存
`W` 的自乘积并把偏置折叠进去，主循环每个元素只需 `n/2` 次乘法。
实现见 `src/linear.cpp`，完整推导、缓存策略和实测见
[docs/linear_layer.md](docs/linear_layer.md)。

`./bench` 会自动运行线性层测试，也可以只测指定形状：

```bash
./bench --fc-shapes 256:1024:1024,128:784:256
```

在本机 `128×512×512` 的层上，乘法从 3355 万降到 1694 万，耗时从 10.5 ms
降到 6.4 ms（约 1.66 倍）；`256×1024×1024` 上从 89.5 ms 降到 49.8 ms。

## 7. 说明

- 这里比较的是**算法变换本身**，所有实现都是未分块、未向量化的朴素循环；
  生产环境应直接使用 BLAS（OpenBLAS/MKL）的 `dgemm`，其性能远高于两者。
- `matmul_winograd` 需要额外的 `O(m+p)` 存储和一次按列遍历 `B` 的预处理，
  这些开销也计入计时。
- 想观察 cache 分块的影响，可以在 `matmul_*` 外层加分块循环，再比较三者。
